- **Connections.** Every schema-owner write and every inspect uses the migration connection selector of the B2 Window 2 precedent (main packet ruling D4(a)). The runtime role name and its connection key are read only into the tool process memory (ruling D4(b)).
- **No role name in argv** (set B K5). No step passes `--runtime-role` to any CLI. SC-1 to SC-3 take no runtime role. The further runtime-role inspections run in process through the staged tree's exported `inspect*` functions with the role from memory, as the set B grant module does (K1).
- **One runtime role value** (Root ruled SB209 item 1 (a) and SB214 item 2). SM reads the runtime role once at the gate into memory and refuses `SETC_STOP_DB_STATE` before any unit command if it is empty, absent or fails the role-name rule. SM passes that one value to every child and call and uses it for the G1-G9 M6 EXACT classification and every migrate, inspect, grant and revoke call. The grant CLI and the M6 CLI read their role from their own runtime connection (product code, unchanged); SM's owner check before the grant and the revoke compares that connection with the gate value (recorded difference SM-11, section 5.2).
- **Owner path** (Root ruled SB207 item 3). SC-4 refuses unless current_user is exactly the owner of `quant_jobs`. Expected selector class: OWNER. (Root checked the accepted set B B0 records before install (SB415): they hold the selector role but no class read, so the class is not taken from them. The owner session role is set only on SM's owner (migration) connection, through the connection string options parameter or an explicit SET ROLE on that connection. - **Digests** (Root ruled SB211 item 2, SB214 items 1 and 9, SB218 item 2, SB223 item 2). The unrelated-ACL digest of the grant module covers the public schema objects, column ACLs, the database and the default ACLs; it does not cover other schemas, types or languages. It includes object identity, so SC-4 (new functions) changes it by design. It is compared only immediately before and after SC-7 (the CLI's in-transaction `other_acl_unchanged` plus an SM read on each side) and around each unwind step, never from the gate to the end of the window. The run and step digests are read after both units are stopped (SM: after the window dump; SMR: after the lock-free wait); the gate read is a record only. Format, the one SV binds from the SM receipt: `{runs:{n, fp}, steps:{n, fp}}`, where n is the row count of `public.quant_jobs` (runs) or `public.quant_job_steps` (steps) and fp is 64 lowercase hex characters of SHA-256 over the UTF-8 text of the rows, each row as its row-to-text cast, sorted by that text in C collation and joined with a line feed (empty set: the hash of the empty string). Each read uses the `R0_RUNS` and `R0_STEPS` statement text verbatim, in its own read-only transaction, with TimeZone UTC, DateStyle `ISO, YMD` (the R0 gate session value; confirmed SB223 item 2), extra_float_digits 1 and bytea_output hex.
- **One transaction per step** under the `robot:maintenance` try-lock (each module enforces it). A refusal leaves that step's objects unchanged.
- **Re-inspect after any stop** (Root ruled SB207 item 1). After any stop, and before any restart, SM re-inspects all seven step states (SC-1 to SC-7) and records them in the receipt. A lost commit acknowledgement is resolved by this re-inspection, never by a retry. Every unwind and stop decision uses the re-inspected state (Root ruled SB209 item 1 (c), SB214 item 4). Unknown outcomes, each resolved by re-inspection: a lost COMMIT acknowledgement; a grant or revoke refusal whose COMMIT outcome is unknown, including the product label `DATABASE_ERROR` (Root ruled SB211 item 2, SB214 item 10, SB219 item 5); in SMR, an operation that passes its bound, which is cancelled on a second connection (or, when no backend of it is visible, by closing its pool connection) and waited for before the re-inspection, with a backend that cannot be ended giving UNENDED and holding both units (Root ruled SB217 item 7, SB220 item 1). SM does not gate on the grant CLI `--inspect` exit code (ABSENT includes the partial register-only state); it reads the state line (Root ruled SB211 item 2, SB214 item 10).
- **Output.** Raw CLI output, stacks and the inspect JSON stay private on the host. Only mapped labels, states, counts, booleans and digests leave (OPS1-E9 form).
- **No retry** under a GO. A pin change after a GO voids it.
- **Throwaway isolation (R0 and R).** Before every write to a throwaway cluster, the tool reads the cluster's system identifier and data directory and refuses unless they equal the throwaway it created in this job. No write may reach the staging database through a rehearsal path. A logical dump carries no roles, so the tool creates the grants-v4 role set, including a runtime role, on every throwaway before the restore; probes use SET ROLE on the throwaway only, never the staging runtime credential (Root ruled SB207 item 4).
