The harness deadline is 120 seconds including setup. A case deadline is 30 seconds, with actual cancellation or connection termination and rollback; a timer rejection alone is insufficient. A deadline overrun or unknown cleanup state fails the run and requires root recovery. It terminates only its owned runner process tree when required, then stops the exact recorded cluster. No automatic retry, larger cap or additional experiment follows a failure.

Before starting, require at least 768 MiB free physical memory, 2 GiB free disk and no other fixture PostgreSQL processes. Request a resource sample after each one-second interval; record actual sample timestamps and gaps. Each inventory command has a six-second external timeout; slow probes fail the run. Stop if free memory falls below 384 MiB, runner process-tree RSS exceeds 192 MiB, the conservatively summed RSS of observed PostgreSQL processes exceeds 256 MiB, or free disk falls below 2 GiB. No PostgreSQL process exists at admission. A later unrelated PostgreSQL process can make this conservative global abort signal fire; it never authorizes terminating that unrelated process. Summed PostgreSQL RSS can count shared pages more than once. These are conservative sampled abort signals, not a hard memory cap or proof of transient peak usage. The small row ceiling and explicit admission budgets bound this initial experiment's data scale. Larger performance cells require a separate admission packet.

Every exit path attempts `pg_ctl` fast stop against the recorded owned data directory, checks stopped status and preserves logs. The root verifies the recorded PostgreSQL PID has exited and the loopback listener is closed. Retain the stopped data directory for review; no recursive deletion is authorized by this packet. Remove only the runner's password tempfile. Never touch retained data from earlier experiments.
