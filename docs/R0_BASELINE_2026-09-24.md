## Source integration findings

The repository transport copy `tradingview/spt_pro_v4_robot_trade.pine` has SHA-256 `48528F49843C702995F43ECDB995D36C23DDD00D7C06CCACF31BD3AC76EA3C3B`. Ignoring line endings, its diff against the original has **two edits before the appended block**: a `Robot Trade (Spot)` option added to `notifyExtra` near line 392, and a changed `f_sendNotify` guard near line 1712. A 162-line transport block starts after the original body near line 2493. The copy is therefore not append-only under the revised Step 2 rule. It also lacks independent Bridge ATR Multiplier for SL and RR inputs, despite those defaults existing in the separate Bridge template. The original has its own SL/TP/RR settings; those remain source logic and must not be rebound to the new Bridge pair.

The original's native `alert()` calls matter for an append-only adapter: a TradingView alert configured for **Any alert() function call** would also see those calls. APP-3A must select a supported alert configuration that avoids duplicate or non-execution payloads while preserving the original code. Turning off native notifications through an existing input is a candidate configuration, subject to signal review; it is not yet verified in TradingView. The SPT source is **Webhook candidate**, not yet **Optimization supported** or **Export validated**.
