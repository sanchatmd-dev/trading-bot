## Closed internal representation

A request registry has exactly `version`, `unions`, `windows`, `bindings`, `charges`. Version is `qr2-coverage-snapshot-v1`. A union is `{id,market,window,fact}` with one supported market, an aligned nonempty window and either `{state:'COMPLETE',timestamps:[...]}` or `{state:'TABLE_ABSENT'}`. A window is `{id,market,resolved_range,union_id,start_index,end_index,expected_minutes,stored_minutes,missing_minutes,interval_count}`. A binding is `{bot_id,broker,window_id}`. Charges are `{union_minutes,timestamp_rows,unique_windows,derivation_visits,output_intervals,input_bytes_upper_bound,output_bytes_upper_bound}`. IDs are zero-based array indexes assigned deterministically. Only plain JSON data crosses the future worker seam.

The supported market is exactly the Stage 1 identity. Unsupported brokers use null; never infer BTCUSDT for another broker. Bindings come from independently authorized account metadata. Stage 2A receives that metadata explicitly and cannot establish authorization itself. Reject duplicate account identities and mismatched broker/market identities. Only the existing binance-global, binance-th, innovestx and settrade brokers are permitted; binance-global requires the exact supported market and the other three require null. Validate registry bindings against the supplied metadata, including each resolved range; do not use a registry to validate itself.

Deduplicate equal market and full resolved range, preserving different partial edges even when inspected windows match. Sort deterministically by market identity and numeric range, null first. Merge overlapping or touching inspected windows for each supported market; keep disjoint unions separate. Windows reference their containing union. COMPLETE windows use exact half-open array indexes selecting closes in `(L,U]`. TABLE_ABSENT uses null indexes/counts. Unsupported windows have null indexes/counts; supported null or no-full-candle windows have null indexes and zero counts. These cases have no union and use the Stage 1 NOT_NEEDED semantics. Zero bindings yields empty arrays and zero work cardinalities (union_minutes, timestamp_rows, unique_windows, derivation_visits and output_intervals). Both byte charges remain nonzero conservative bounds on the empty registry and empty publication envelope; a byte budget below this overhead refuses even an empty request.

Every window and union must be referenced; every binding resolves exactly once. Store each union's timestamp array only once. No registry or timestamp array is copied into a member. Future reader integration attaches only a window ID to each member snapshot, and one registry to the owner snapshot. Stage 3 constructs each distinct coverage object once.

## Read and failure contract

The new read seam requires an existing verified READ ONLY REPEATABLE READ (or stricter serializable) transaction; it cannot silently begin a weaker transaction or accept arbitrary external connections. Require the existing database seam's isTransaction === true before any query, then check isolation and read-only before any table probe. Session SHOW values alone do not establish an active transaction. The later owner integration must finish all existing account admission before this seam or any detail materialization. Stage 2A alone does not prove that owner ordering.

For nonempty supported unions, probe `public.pine_market_bars` once. No probe for only unsupported/empty domains. Use bound identity/range/limit parameters and `SELECT bar_time::text AS bar_time FROM public.pine_market_bars WHERE broker=$1 AND symbol=$2 AND timeframe=$3 AND bar_time>$4::bigint AND bar_time<=$5::bigint ORDER BY public.pine_market_bars.bar_time LIMIT $6`. Qualify ORDER BY with the numeric table column: the unqualified name could resolve to the text output alias and sort lexicographically. Include mixed decimal-width timestamps in real PostgreSQL verification. Do not fetch OHLCV/provenance payloads or filter misaligned rows out. Option M adds no retrieval-time predicate; existing price lookup remains separate.

One aggregate row budget spans all unions. Each completed query uses checked effectiveAllowance+1, where effectiveAllowance is the minimum of the remaining timestamp-row budget and the retained-row capacity already admitted by the conservative input-byte budget. Exact-budget results succeed only if no sentinel is returned. At zero remaining, the next union still performs LIMIT 1 (or refuses the whole request); it cannot be silently declared empty. Any sentinel, later source error or admission failure invalidates the whole registry. No partial success, retry, range clipping, truncation or backfill. Missing rows alone do not refuse a report; table absence is explicit UNAVAILABLE, not an empty observed table.

Decode canonical primitive decimal strings only (`0` or a nonzero digit followed by digits), at most 16 characters and value no greater than MAX_SAFE_INTEGER before Number conversion. Then require nonnegative, aligned, strictly increasing unique closes inside the union. Reject numeric driver values, signs, whitespace, fractions, exponents, leading zeros and unsafe bigint values. A source error never becomes TABLE_ABSENT. Use `QR2_RANGE_ADMISSION_REFUSED` for resource overflow, `QR2_INPUT_INVALID` for malformed caller budgets/metadata and `QR2_REPORT_FAILED` for source/registry corruption or invalid transaction facts; no new public error code.

## Allocation admission

Explicit positive safe-integer budgets cover `union_minutes`, `timestamp_rows`, `unique_windows`, `derivation_visits`, `output_intervals`, `coverage_input_bytes`, `coverage_output_bytes`. Zero remaining rows during execution is valid and still needs the sentinel probe. A fixed maximum of 20 supplied bindings matches the existing account ceiling; this does not expand reachable owner membership. Reject malformed budgets before database work. No unbounded missing-minute bitmap or minute-grid enumeration.

Check metadata/window/span and conservative minimum input/output byte bounds before reads. Before each query, bound fixed registry metadata (including charges and maximum scalar widths) and reserve conservative retained-timestamp bytes across all unions. A safe upper bound is 17 JSON bytes per numeric timestamp including its delimiter; an equally proved conservative bound is permitted. Compute byte-admitted row capacity before materialization and clamp query allowance to the smaller of that capacity and remaining timestamp_rows. Limit materialized driver rows to this allowance plus one sentinel; validate and release row-object references, retaining only one numeric array per union. A returned sentinel refuses the whole request even when the row-count budget alone had room. The one sentinel is bounded temporary evidence, never retained in a successful registry; include its driver/object peak in later measurements. The serialized-input budget is not a hard heap cap, and this protocol does not claim otherwise. Before interval arrays or public objects could be allocated, derive exact window slice indexes and interval counts by bounded passes, charging the canonical per-window workload against `derivation_visits`. Deduplicated windows are processed once. Check aggregate output intervals and conservative JSON bytes before returning a registry. This stage need not allocate public interval objects.

The canonical charge is exactly sum(end_index - start_index) over distinct COMPLETE windows; other windows contribute zero. It counts overlapping windows separately, while timestamp_rows counts union storage once. It is not total execution operations or a lifetime validation budget. The admitted pass schedule is one strict decode per union in the reader, one union validation plus one per-window derivation during construction, and at most one final independent registry validation per invocation. That validator performs at most one union validation and one per-window derivation plus bounded boundary searches. Equivalent code may do no greater work; document its pass schedule. No recursively repeated build/validate, full-array filtering per account or missing-minute enumeration. Future consumers must measure their additional validation passes.

For byte accounting, the account fragment is exactly {market_data:{coverage:C}}, with C the Stage 1 output. The owner fragment is exactly {market_coverage:{version:'qr2-owner-bar-coverage-v1',entries:[{id:'coverage:0',coverage:C},...],accounts:[{bot_id,broker,coverage_ids:['coverage:0']},...]}}. Every binding has exactly one public ID, the literal coverage: prefix plus its decimal window index; entries follow window order. output_bytes_upper_bound bounds the maximum of the owner fragment and any single account fragment. With no windows it bounds the empty owner fragment. Wrapper overhead may be conservatively counted even when later merged into an existing financial object. This defines the prospective envelope for admission and tests; it does not publish it now.

Byte accounting must be an explicit conservative, checked algorithm: include every JSON key/value, commas, brackets, escaped UTF-8 identifiers, references and prospective interval objects. It must never underestimate the actual registry or eventual coverage envelope. Check scalar lengths before expensive copying/escaping. A final actual registry UTF-8 byte check is allowed only after conservative preallocation admission. Include the charge object itself in the input estimate, reserving the maximum safe-integer decimal width to avoid self-reference undercounting. Test-only materialized envelopes must verify bounds for all states, partial edges, multiple references and non-ASCII/escaped identifiers. Serialized bytes are not a heap guarantee. Resource measurements must include driver rows, numeric arrays, temporary slices, clone and serialization. The byte accounting covers the coverage registry and coverage envelope only, not the entire existing financial response; later integration must keep those meanings explicit.

The closed validator independently recomputes derived bounds, slice indexes, counts, reference consistency and charges under the supplied budgets. It applies cheap array/metadata limits before traversing untrusted arrays. After independent metadata/budgets and their plan are qualified, any registry structural, derived-value or resource-envelope violation is QR2_REPORT_FAILED: the supplied registry is invalid for that context. This includes a structurally consistent registry larger than the validator context allows. Reject at the cheap budget boundary without traversing an oversized payload to infer intent. Builder/reader admission remains QR2_RANGE_ADMISSION_REFUSED, and malformed independent arguments remain QR2_INPUT_INVALID. Structural success never proves a database read or authorization. Function names are ordinary implementation choices; document the API for the independent tester before returning.
